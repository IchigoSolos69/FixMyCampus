# Demonstration walkthrough

Start the app and seed local demo data using the README. Use separate browser profiles/private windows for actors so their sessions remain independent. All demo accounts use `CampusDemo!2026`. Mailpit at `http://localhost:8025` captures account and workflow emails.

1. **Student reports an ordinary issue.** Sign in as `student@campus.test`. Choose **Report an issue**, select Classroom Infrastructure, enter a building/room and a description of at least 15 characters, and optionally attach a real JPEG, PNG, or PDF. Submit. Record the `CMP-YYYYMMDD-NNNN` reference. Check the Submitted timeline entry, Medium priority, service deadline, and notification.
2. **Incharge triages and assigns.** In a separate window sign in as `incharge@campus.test`. Open the complaint queue; search by reference and combine status/category/date filters. Open the issue. Select **Verify report**, then **Assign department**, retain Civil Engineering, and supply a reason. Inspect the timestamped history and assignment chain. Optionally change priority before resolution and confirm the deadline uses the original cycle start.
3. **Civil officer works and resolves.** Sign in as `officer1@campus.test`. The issue appears in the department queue; an IT officer (`officer4@campus.test`) cannot access it. Choose **Start work**, then add a progress update. Add optional proof under Attachments before resolving. Select **Mark as resolved** and enter at least a 10-character summary.
4. **Student sees the outcome.** Within five seconds of the recorded change, the tracking screen updates. Inspect resolution, proof, and timeline. Submit a 1-5 rating and optional comment. The submitted feedback is read-only. Choose **Reopen complaint** within 72 hours with a reason; the issue returns to Assigned with a new service deadline while earlier history and feedback remain.
5. **Returned report correction.** Open the seeded Returned furniture issue as the Student. Read the Incharge's reason, correct its location/description, optionally add evidence, and resubmit. The current category is retained. The current SLA start is not reset.
6. **Critical confidential route.** As Student open the dedicated urgent-report path (`/complaints/emergency`), which lists only the four emergency categories. Create a Mental Health Concerns or Anti-Ragging complaint and select **Submit anonymously**. The form announces immediate Critical routing. Check it becomes Assigned without Incharge verification. Sign in as the relevant officer (`officer9` for welfare, `officer10` for Anti-Ragging) and Incharge: reporter account identity is hidden. An unrelated department cannot read/search/download the case. An Administrator sees aggregates and redacted escalation alerts, not its case detail. For a non-anonymous sensitive submission, permitted handlers can see identity.
7. **Administration and reports.** Sign in as `admin@campus.test`. Inspect People & access, departments, category routing, and SLA/email settings. Assign an officer exactly one department; public registration cannot grant this role. Rename a category and confirm its emergency/confidential classification remains. In Reports & insights choose category/department/status/SLA, a date range, and download CSV and PDF. View department averages/medians, ratings, and SLA trends on Overview. Incharge can view only the category summary and cannot export.
8. **Account flows.** Create a unique `@campus.test` account, open its verification email in Mailpit, confirm it, then sign in. Request a password reset and follow the single-use 30-minute link. Profile edits are audited; password changes require the current password and invalidate existing tokens.

Use the dedicated integration tests to exercise expired windows, lockout, concurrent references, SLA breaches, and immutable records. Do not alter production timestamps for a demonstration. For a live walkthrough, an SLA breach can be demonstrated by setting a short SLA on a disposable evaluation deployment and waiting; the minimum administrative setting is one hour.

## Acceptance exercise

Time a new user's login-to-report-confirmation attempt; target under 90 seconds. Test the primary forms using keyboard alone at desktop and 390-pixel width. Confirm visible focus, readable errors, and status text as well as status color. Check network requests contain Bearer access tokens, and local/session storage contains no access token. Complete the captured-email browser flow and restore rehearsal before considering production rollout.
